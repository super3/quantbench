# quantbench

Most published LLM benchmarks are run at full precision, but almost nobody runs models that way. Consumer and shared hardware forces people down to 8-, 5-, or 4-bit quants, and the common rule of thumb — "quality holds up fine until you get to about Q4" — is mostly folklore backed by perplexity or KL-divergence numbers against the FP16 reference. Those metrics are cheap and easy, but they only tell you how far the output distribution drifted, not whether the model can still do the task you care about.

quantbench measures the thing people actually care about: **task loss on real benchmarks as a function of quantization**. The goal is to take a set of open-source models, run them across the practical quant ladder (FP16 → Q8 → Q6 → Q5 → Q4 → Q3 and below), and score them on real evals rather than on divergence from their own full-precision output — so we can say where accuracy actually falls off, which capabilities degrade first (reasoning and long-context tend to break before short factual recall), and whether the answer differs by model family, size, and quant method.

The secondary question is everything else that moves with precision in a real deployment. Context length, KV-cache quantization, quant format and calibration data, and the memory/throughput tradeoff all interact with bit width, and a benchmark that holds them fixed at defaults misses most of what a practitioner has to decide. The intended output is a practical map: for a given VRAM budget, which model at which precision and context size gives the most real-world capability.
